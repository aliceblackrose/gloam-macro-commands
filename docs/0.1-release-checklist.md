# gloam-commands 0.1 release checklist

This checklist defines the release gate for the first supported `gloam-commands` release. A release should not be cut from an intermediate Phase 11 branch.

## Runtime behavior

- [x] Before-command hooks are implemented and covered by ordering tests.
- [x] After-command hooks are implemented and covered by success/failure behavior tests.
- [x] Centralized command-error handling is implemented and covered by runtime tests.
- [x] Optional `tracing` integration is available without installing or configuring a subscriber.
- [x] Tracing fields have been audited to ensure interaction tokens and sensitive payload values are never emitted by built-in framework lifecycle events.
- [x] Framework-wide command concurrency is bounded without queued waiter tasks.
- [x] Per-command concurrency composes with the framework-wide limit.
- [x] Command execution policy is deterministic and independent from handler business logic.
- [x] Autocomplete uses its own interaction response path.

## Public API

- [x] Run a complete public API documentation audit.
- [x] Confirm every public runtime item either has useful rustdoc or is intentionally `#[doc(hidden)]`.
- [x] Confirm public error variants and dispatch outcomes describe their runtime semantics accurately.
- [x] Confirm examples use only supported public APIs.
- [x] Confirm no prefix-command, message-content, or hybrid-command API has entered the public surface.
- [x] Confirm semver-sensitive names and signatures are acceptable for 0.1.

## Examples and integration documentation

- [x] Add a basic managed slash-command example.
- [x] Add a typed-option / typed-choice example.
- [x] Add a grouped-command example.
- [x] Add an autocomplete example.
- [x] Document manual dispatch inside an existing Gloamwire Gateway loop.
- [ ] Run `cargo check --examples` on the exact release candidate.

## Validation

Run all validation on the exact release candidate commit using Rust 1.98:

```text
cargo fmt --all -- --check
cargo test --workspace --all-targets --all-features
cargo check --workspace --examples --all-features
cargo clippy --workspace --all-targets --all-features -- -D warnings
RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps --all-features
```

- [ ] Formatting passes.
- [ ] Workspace tests pass.
- [ ] Trybuild UI tests pass.
- [ ] Clippy passes with warnings denied.
- [ ] Rustdoc builds with warnings denied.
- [ ] Every example compiles.
- [ ] GitHub Actions is green for the exact release candidate SHA.

## Metadata and repository state

- [x] Workspace repository URLs use the current canonical GitHub owner.
- [x] The pinned Gloamwire revision resolves from the current canonical repository URL.
- [x] The workspace intentionally ignores `Cargo.lock`; the Gloamwire git dependency is pinned by immutable `rev` instead.
- [x] Package descriptions, license metadata, repository metadata, and Rust version are correct.
- [x] `README.md` describes the supported feature set and explicit non-goals accurately.
- [x] `ROADMAP.md` marks only completed Phase 11 work as complete.
- [ ] No stale phase branches or obsolete release-only files remain unintentionally.

## Release preparation

- [ ] Decide whether 0.1 is published to crates.io immediately or tagged as a repository-only release first.
- [ ] If publishing, verify both runtime and proc-macro package names and ownership are available/configured.
- [ ] Verify package contents with `cargo package --list` for each publishable crate.
- [ ] Verify packaged crates build independently from workspace-only assumptions.
- [ ] Prepare concise release notes covering the supported slash-command feature set and explicit non-goals.
- [ ] Create the `v0.1.0` tag only after the exact tagged commit has passed every validation item above.
